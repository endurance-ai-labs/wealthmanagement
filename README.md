# Rosemont Partners — Private Wealth Portal

A demonstration environment for a **fictional** registered investment adviser, built by
Endurance AI Labs. Live at **endurancelabs.ai/wealthmanagement**.

Rosemont Partners, LLC does not exist. Every household, account, holding, fund, manager,
person, document and figure in this repository is synthetic and generated for illustration.
Index and benchmark names are real; the levels and returns attached to them are not.
Nothing here is investment, tax or legal advice.

## What it is

25 pages across seven navigation groups, 11 role personas with real permission gating,
9 approval chains, and a seeded dataset that reconciles across every screen.

| Group | Pages |
|---|---|
| Home | Firm command centre / client portfolio overview |
| Clients | Client Book, Household Book, Household Detail (11 tabs), Reporting Center, Document Vault, Meeting Desk |
| Portfolios | Models & Allocation, Trading & Rebalancing, Performance & Attribution, Risk Analytics |
| Research | Global Markets, Fund Research, Fund Tearsheet, Manager Due Diligence, Investment Committee, Private Markets |
| Planning | Wealth Planning, Tax & Estate |
| Firm | Revenue & Billing, Growth & Pipeline, Compliance, Operations, Team & Capacity |
| Assistant | Rosemont Brain (page plus a floating assistant on every page) |

Plus a public landing page at `/welcome/`.

## Architecture

Static, client-side only. No server, no build step, no live data feeds.

```
js/util.js      formatters, personas and permissions, approval chains, e-signature
js/markets.js   98 benchmarks across seven boards, Treasury curve, credit spreads, macro
js/funds.js     70 funds across 25 vehicle types, 22 manager files, capital market assumptions
js/data.js      firm, households, accounts, positions, tax lots, transactions, performance
js/world.js     each client's real world: family, career, property, held-away assets, life events
js/nav.js       navigation, market tape, headline marquee, theme and view-mode toggles
js/brain.js     the floating assistant
pages/*.js      one file per page; the HTML shells are generated by scripts/shells.py
```

Everything is generated once from fixed seeds, so the same numbers appear on every load
and every machine.

## Tests

```
node scripts/tieout.js   # data integrity: does everything reconcile
node scripts/smoke.js    # renders all 25 pages under 4 roles, catches TDZ and reference bugs
python scripts/shells.py # regenerate the HTML page shells
```

`tieout.js` asserts the rules the build was specified against: household value equals the
sum of its accounts, positions and tax lots; firm AUM equals the detailed book plus the
tail; revenue equals the fee schedule applied to assets; the roll-forward closes; allocation
sums to 100% at every level; called plus uncalled equals commitment; and model returns
reproduce their blended benchmark.

Following the portal-learns-from-bugs pattern, every bug found becomes a new check.

## Local preview

The base path is `/wealthmanagement/`, so serve a directory containing a folder of that name:

```bash
mklink /J C:\Users\<you>\.rp-serve\wealthmanagement C:\Users\<you>\wealthmanagement
npx serve -l 5251 C:/Users/<you>/.rp-serve
```

Then open `http://localhost:5251/wealthmanagement/`. Access code: `enduranceportal`.

## Notes

- Base path `/wealthmanagement/` is hardcoded throughout and matches the repository name, so
  the GitHub Pages URL and the proxied URL resolve identically. The nav path normaliser
  slices by `BASE.length`, not a hard-coded number.
- Page constants used by render helpers must be declared **above** `boot()`, or they are
  still in the temporal dead zone when the first render runs. `scripts/smoke.js` catches this.
